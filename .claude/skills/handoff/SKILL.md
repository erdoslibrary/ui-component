# handoff — 세션 인계

현재 세션에서 진행된 작업을 다음 세션이 **읽고 즉시 이어서 실행할 수 있도록** 단일 인계 파일에 체크리스트 형태로 정리한다.
장식이나 추측성 서술을 배제하고, **실제 검증된 사실(증거)**과 **실패한 시도(반복 방지)**를 명확히 남긴다.

## 대상 파일

- 사용자가 파일명을 지정하면 해당 파일(`STATE`, `.handoff.md` 등)을 사용한다.
- 별도 지정이 없으면 프로젝트 루트의 **`.handoff.md`** (또는 기존에 존재하는 **`STATE`**)에 작성한다.
- 파일이 이미 존재하면 **먼저 읽고 갱신**한다. 완료된 항목은 `[x]`로 전환하고, 유효한 미완료 항목은 이월(carry-forward)한다. 단순 덮어쓰기가 아닌 **현재 상태의 정확한 스냅샷**을 유지한다.

## 작성 절차

1. **실제 컨텍스트 및 증거 수집 (추측 금지)**:
   - 일시 및 브랜치 확인: `date '+%Y-%m-%d %H:%M'`, `git branch --show-current`
   - 변경 사항 파악: `git status --short`, `git diff --stat` (신규 파일 및 수정 파일 점검)
   - 검증 증거 확인: 이번 세션에서 실행한 테스트, 린트, 빌드, 스크립트 실행 결과 및 구체적인 파일:라인 위치 확인
2. **정직한 3대 구획 분류**:
   - **✅ 무엇이 됐나 (검증된 증거와 함께)**:
     - 테스트/빌드 성공이나 동작 확인이 끝난 항목만 `[x]`로 기록.
     - 반드시 구체적인 증거(`명령어`, `결과`, `파일:라인`)를 함께 명시한다.
     - 증거가 없는 항목은 미완료(⏳)로 분류한다.
   - **❌ 무엇을 시도했고 실패했나 (반복 방지)**:
     - 시도했으나 실패했거나 막힌 접근법, 에러 내용 및 원인을 명시.
     - 다음 세션에서 동일한 시행착오를 반복하지 않도록 교훈/대안을 남긴다.
   - **⏳ 다음 할 일 + 아직 안 한 것**:
     - 다음 세션에서 바로 실행해야 할 구체적인 작업(진입점 파일/실행할 명령어 명시).
     - 아직 착수하지 않은 요구사항 및 백로그 목록.
3. **파일 쓰기 및 알림**:
   - 아래 템플릿에 맞춰 파일을 생성/갱신하고, 저장 경로와 요약을 사용자에게 보고한다.

## 출력 템플릿

```markdown
# 🤝 Handoff — <현재 작업 상태 한 줄 요약>

> 갱신: <YYYY-MM-DD HH:MM> · 브랜치: `<branch>` · 변경: `<git status --short / git diff --stat 요약>`

## ✅ 무엇이 됐나 (검증된 증거와 함께)
- [x] <완료한 작업 1> — 증거: `<실행 명령 / 파일:라인 / 테스트 통과 결과>`
- [x] <완료한 작업 2> — 증거: `<검증 내용>`

## ❌ 무엇을 시도했고 실패했나 (반복 방지)
- [ ] <시도했던 접근 방식> — 원인: <실패 원인 및 에러> → 교훈/대안: <다음 시도시 피해야 할 점>
<!-- 실패한 시도가 없으면 "- 없음" -->

## ⏳ 다음 할 일 + 아직 안 한 것
- [ ] <바로 착수할 다음 작업> — 시작점: `<관련 파일 경로 또는 명령어>`
- [ ] <아직 착수하지 않은 작업>
- [ ] <추후 고려할 사항>

## 📌 인계 메모 (선택)
- 제약/주의사항: <환경 변수, 의존성, 특별한 설정, 설계 결정 이유 등>
```

## 작성 원칙

- **체크리스트 형태 유지**: 항목은 `- [x]` 및 `- [ ]` 형식으로 관리하여 진행 상황을 즉시 파악할 수 있게 한다.
- **간결성 및 가독성**: 각 항목은 불필요한 장황한 문장 없이 1~2줄로 핵심만 명확히 작성한다.
- **다음 세션 중심**: "내가 무엇을 했는지"의 나열이 아니라, "다음 세션이 즉시 업무에 투입되기 위해 무엇을 알아야 하는지"에 집중한다.
- **규칙 준수**: 불필요한 장식이나 마케팅 문구를 배제하고 직관적인 정보 위계만 사용한다.
